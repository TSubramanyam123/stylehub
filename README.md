# StyleHub – Full-Stack E-Commerce Application

## Project Overview

StyleHub is a full-stack e-commerce web application that allows users to browse products, add items to their cart, place orders, and make payments securely using Stripe test mode.

The application uses FastAPI for backend API development and React for the frontend. JWT authentication is used to protect user-specific operations.

## Project Objectives

* Develop a user-friendly online shopping application.
* Implement user registration and login.
* Create REST APIs for products, cart, and orders.
* Integrate a database to store application data.
* Implement secure authentication using JWT.
* Integrate Stripe for payment processing.
* Update order status through Stripe webhooks.

## Installation and Setup

### Prerequisites

Install the following tools:

* Python
* Node.js and npm
* Git
* Stripe CLI
* A supported SQL database

### 1. Clone the Repository

```bash
git clone YOUR_GITHUB_REPOSITORY_URL
cd stylehub
```

Replace `YOUR_GITHUB_REPOSITORY_URL` with your actual GitHub repository URL.

### 2. Set Up the Backend

Open a terminal:

```bash
cd backend
python -m venv venv
```

Activate the virtual environment on Windows:

```powershell
.\venv\Scripts\Activate.ps1
```

Install dependencies:

```bash
pip install -r requirements.txt
```

Create a `.env` file using `.env.example` as a reference and configure the required database, JWT, CORS, and Stripe settings.

Do not commit `.env` or any real secrets to GitHub.

Start the backend:

```bash
python -m uvicorn app.main:app --reload
```

Backend URL:

`http://localhost:8000`

API documentation:

`http://localhost:8000/docs`

### 3. Set Up the Frontend

Open another terminal:

```bash
cd frontend
npm install
npm run dev
```

Open the local URL printed by Vite, usually:

`http://localhost:5173`

### 4. Configure Stripe Test Mode

Configure the Stripe publishable key, secret key, and webhook signing secret in the backend environment and the appropriate frontend configuration.

Use Stripe test mode and Stripe's documented test payment details. Never use real payment credentials in the test environment.

Start the Stripe CLI listener:

```bash
stripe listen --events payment_intent.succeeded,payment_intent.payment_failed --forward-to http://localhost:8000/api/v1/webhooks/stripe
```

Use the webhook signing secret generated by the running listener as the backend's `STRIPE_WEBHOOK_SECRET`. Restart the backend if the environment configuration changes.

Keep Stripe CLI running while testing local webhook events.

## API Endpoints

The API base path is:

`/api/v1`

| Module         | Endpoint                        | Method |
| -------------- | ------------------------------- | ------ |
| Authentication | `/auth/register`                | POST   |
| Authentication | `/auth/login`                   | POST   |
| Products       | `/products`                     | GET    |
| Cart           | `/cart`                         | GET    |
| Orders         | `/orders/create-payment-intent` | POST   |
| Orders         | `/orders`                       | GET    |
| Orders         | `/orders/{order_id}`            | GET    |
| Stripe webhook | `/webhooks/stripe`              | POST   |

The exact endpoints available depend on the router implementations in the project. Visit `/docs` to see the registered API routes.

## Payment Workflow

1. The user logs in to StyleHub.
2. The user browses products and adds items to the cart.
3. The backend creates an order and a Stripe PaymentIntent.
4. The frontend confirms the payment using Stripe.
5. Stripe sends a payment event to the webhook endpoint.
6. The backend verifies the event signature and updates the order status.
7. The Orders page displays the latest order status.

A successful payment should result in the order status `paid`.
